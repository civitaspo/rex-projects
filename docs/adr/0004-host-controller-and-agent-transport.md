# Use one host-owned controller and scoped run mailboxes

Multiple Projects on one machine need one scheduler and one SQLite ownership boundary. Coding Agents use provider-specific automatic permissions; a workspace sandbox may deny access to the host state database, and SQLite WAL readers may also require `-shm` writes. Do not run a controller process per Project or make Agent CLI operations depend on shared database access.

Run one foreground Rust machine controller in Rex. It owns SQLite, schedules one logical Supervisor per Project, and launches bounded Agent turns through Rex. Every Project-owned database row carries its Project ID. The controller checks the machine-wide process lease and generation before scheduling work or applying effects.

Give each Agent attempt a unique mailbox inside its exact provider writable workspace. Provide only a scoped run ID, attempt epoch, request set, and opaque channel identity. Agent commands read the controller-published input projection and write bounded JSON requests through same-directory temporary files and atomic rename. The machine controller validates the request against current role and revision, commits it to SQLite, then writes a receipt. A request left in a file while the controller is stopped remains queued, not accepted. Artifact contents stay in the Agent workspace until the controller validates and copies them to its durable store.

Treat Agents as fallible collaborators under the user's OS identity. Preserve personal hooks, instructions, skills, MCP, and Rex events. Capture a supported interactive login environment once, pass it to direct child processes through a private one-use handoff, and set scoped factory markers before provider startup. Bound shell capture and pause affected actions when credentials expire. Rex's SessionStart hook can emit naming instructions. Prefer its verified naming flag through a user-owned marker-aware wrapper that retains ordinary-session naming and other output. Role contracts forbid shared-session renames. Unknown naming behavior warns without blocking startup or requiring a profile declaration. Restore a changed name only with verified attribution and no intervening human rename. Do not modify personal hook files automatically.

Verify automatic permission settings for each provider rather than assuming a common auto flag or sandbox. Reject marked factory-child invocations of human decision commands before queueing them. This prevents accidental self-approval; Rust role checks still do not isolate deliberate same-user commands or marker removal.
Record known repository instructions superseded by the role contract as ordinary instruction-resolution receipts. They do not wake the Coordinator or create irregularities. Actual forbidden attempts, unexplained effects, and unresolved guidance still use the irregularity path. Preserve personal relay hooks, but separate factory recipients where supported and route delivery instructions through the Coordinator. An out-of-band message never supplies human authority merely by reaching an Agent.

Keep linked worktrees. Prefer native Worker commits when the provider's permissions and configured signing and hooks are verified. A restrictive sandbox uses the host file-manifest broker instead. Fix the mode per turn and independently validate actual Git refs, ancestry, tree, signing, and required authorship in both paths. Reconcile an unexpected direct commit instead of overwriting its index or repeating a stale request. The host owns branch publication, PR creation, merge requests, and merges. Factory role instructions reserve those operations even when repository guidance asks a contributor to publish. Observe unexpected remote effects, fence affected work, and require reconciliation without repeating or deleting external outcomes. Exclusive work-node leases protect owned branches while independent native commits use Git's locks. Disable automatic GC and maintenance in managed clones; only the host runs bounded maintenance outside active or uncertain writer leases.

Required repository rex-projects hooks use the bounded process runner and effect journal. A separate durable execution pool permits checks in independent worktrees concurrently while preserving one writer per worktree. Successful receipts bind the exact head and configuration; they complement remote checks and never authorize deployment.

Human instructions enter through the machine dashboard or host CLI and target the TicketRun Coordinator. The controller persists them, schedules the next bounded Coordinator turn, and may pass a typed stop request to an owned Worker. Do not inject human text into a provider TUI. A provider-specific structured interrupt or resume is an optional adapter capability; otherwise stop and recover a turn through Rex, preserving its workspace.

This removes SQLite WAL and SHM dependencies from Agent CLI calls, makes accepted messages auditable, and avoids a separate HTTP service. Persist wake inputs in `role_wake_inputs` and retain stable role workspaces. Reserve coalesced inputs, execution capacity, and launch intent atomically so a parked session resumes without terminal typing. It adds filesystem mailbox recovery and a machine-level scheduler. Test lost receipts, controller downtime, directory replacement, environment handoff, hook compatibility, multi-Project fairness, and surviving Rex blocks before relying on the protocol.

OpenAI documents `codex exec` for bounded runs and its app-server as a process integration with persistent conversations and interruption. Claude Code documents non-interactive output and session resume. Treat these as adapter-specific features that require versioned checks, not as the mailbox or Rex transport protocol.
